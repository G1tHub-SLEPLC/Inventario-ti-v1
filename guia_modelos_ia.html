Guía de Modelos de IA en Antigravity

Cuándo utilizar cada modelo según la fase y complejidad de tu proyecto.

1. Familia Gemini 3.5 Flash (Rápidos)

Son tus "caballitos de batalla". Extremadamente rápidos y perfectos para iterar sobre código de forma ágil, cambios visuales y tareas rutinarias.

Gemini 3.5 Flash (Low)

Cuándo usarlo: Tienes claro el archivo que hay que modificar y el cambio es muy puntual.

Ejemplo: "Cambia el color del botón IMPORTAR EXCEL a verde oscuro".

Gemini 3.5 Flash (Medium)

Cuándo usarlo: El punto de equilibrio. La tarea no es trivial pero tampoco rediseña el sistema. Necesita leer un par de archivos para entender el contexto.

Ejemplo: "Agrega un checkbox para borrar el Historial de Entregas y actualiza la lógica del botón".

Gemini 3.5 Flash (High)

Cuándo usarlo: Quieres un cambio rápido pero que afecta a varios archivos o necesitas que lea gran parte del proyecto.

Ejemplo: "Cambia la tipografía de toda la aplicación a 'Inter' y redondea todos los botones".

2. Familia Gemini 3.1 Pro (Razonamiento Profundo)

Piensan más lento que Flash, pero analizan los problemas a mucha mayor profundidad. Ideales para lógica compleja y depuración de errores difíciles.

Gemini 3.1 Pro (Low)

Cuándo usarlo: Necesitas mucha inteligencia, pero el problema está aislado en un solo archivo (cálculos matemáticos, algoritmos complejos).

Ejemplo: "Crea una función con expresiones regulares para validar y formatear RUTs matemáticamente en este archivo util.js".

Gemini 3.1 Pro (High)

Cuándo usarlo: Investigar bugs misteriosos que involucran varios componentes y la base de datos, o crear lógicas interconectadas pesadas.

Ejemplo: "La base de datos no está borrando la auditoría aunque no da error en el frontend. Investiga toda la conexión y el flujo". (El modelo deducirá problemas de seguridad RLS en Supabase).

3. Familia Claude (Arquitectura y Refactorización)

La etiqueta (Thinking) significa que tienen una fase de "pensamiento profundo" interno antes de escribir una sola línea de código.

Claude Sonnet 4.6 (Thinking)

Cuándo usarlo: Para refactorizar código desordenado o hacer cambios arquitectónicos grandes pero seguros, manteniendo un código limpio.

Ejemplo: "Divide el archivo InventarioContext.jsx en tres contextos diferentes sin romper la aplicación actual."

Claude Opus 4.6 (Thinking)

Cuándo usarlo: El modelo más pesado e inteligente. Para migraciones masivas, planificación de sistemas desde cero o tareas de altísima ambigüedad.

Ejemplo: "Diseña la arquitectura completa de una nueva app con roles jerárquicos (SuperAdmin, Admin, Usuario) y planifica la migración desde cero."

4. GPT-OSS 120B (Medium)

Cuándo usarlo: Modelo Open Source gigante. Excelente para tareas estándar, redacción técnica, generar plantillas o como una "segunda opinión" cuando otros modelos se atascan.

Ejemplo: "Redacta un README.md detallado explicando cómo instalar y configurar este proyecto en un nuevo computador local."
